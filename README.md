# 습관 별자리 — 노션 연동 버전

체크한 습관 기록이 노션 데이터베이스에 저장되고, 습관 목록은 노션에서 관리하는 버전입니다.

---

## 무엇이 달라졌나

기존에는 기록이 브라우저 안에만 있었고, 새로고침하면 사라졌습니다. 이제는 앱에서 습관을 체크하면 노션 "Daily Logs"에 행이 하나 생기고, 체크를 풀면 그 행이 보관 처리됩니다. 습관 목록도 노션 "Habits"에서 읽어옵니다. 어느 기기에서 열어도 같은 기록이 보입니다.

노션 토큰은 브라우저로 내려가지 않습니다. 앱은 자기 서버(`/api`)에만 요청하고, 노션 호출은 그 서버가 대신합니다.

노션에 연결되지 않은 상태(토큰 미설정, 일시적 오류)에서는 자동으로 브라우저 저장으로 전환되고, 화면 상단에 "이 기기에만 저장 중"이라고 표시됩니다. 앱이 하얗게 죽지 않습니다.

**이번 업데이트 — 회고 탭 덜어내기**

읽어야 하는 글자를 줄이고, 눈으로 바로 읽히는 그림으로 바꿨습니다. 회고 탭 길이가 절반 아래로(2998px → 1624px) 줄었습니다.

- **목표 카드가 막대그래프가 됐습니다.** `4/7` 같은 숫자 대신 **막대 높이 = 그 주 달성률**. 꽉 찬 밝은 막대가 목표를 채운 주라서, 연속으로 채운 구간이 한눈에 보입니다. (정확한 수치는 칸에 마우스를 올리면 나옵니다.)
- **걷어낸 것**: 카드마다 반복되던 기간 문구, 월 눈금, 선택 주 상세 줄, 통계 타일 3개(최근 6주 달성 / 이전 3주 대비 / 최고 연속), 칸 탭 기능, 카드 제목 "별자리 변화". 카드가 7겹에서 3겹이 됐습니다.
- **남긴 것**: 막대 양 끝의 `8/17` · `이번 주`, 우측 상단의 `✦ 2/6`(최근 6주 중 채운 주).
- **별자리 썸네일**에도 숫자 대신 **아래쪽 띠**를 넣었습니다. 띠 길이 = 그 주에 채운 목표 비율. 사람 이름은 왼쪽으로, 날짜는 열 제목으로 한 번만 적습니다.
- **밤하늘 탭**: 헤더의 중복 날짜줄과, 노션 모드에서 눌러도 안내만 나오던 "습관 추가 · 정리"를 감췄습니다. 상대 목표 달성 카드에 있던 ❤️🔥👏 버튼은 **어디에도 전달되지 않는 장식**이라 없앴습니다(응원은 별똥별 편지로).
- 진행률 바는 그대로 두되, 오른쪽 끝에서 이모지가 뚝 잘려 보이던 것을 **서서히 흐려지도록** 바꿨습니다.

## 준비 (처음 한 번만)

### 1단계 — 노션에서 연결 확인

노션의 습관 DB와 기록 DB를 각각 열고, 우측 상단 `···` → **Connections**(연결) 에서 사용 중인 Integration이 추가되어 있는지 확인합니다. 이게 빠져 있으면 토큰이 올바라도 "찾을 수 없음" 오류가 납니다. 가장 흔한 실수 지점입니다.

### 2단계 — Vercel에 토큰 등록

1. https://vercel.com 접속 → `habit-tracker` 프로젝트 클릭
2. 상단 **Settings** → 왼쪽 메뉴 **Environment Variables**
3. 아래 값을 추가하고 **Save**

| Key | Value | 적용 환경 |
|---|---|---|
| `NOTION_TOKEN` | 노션 Integration 토큰 (`ntn_` 또는 `secret_` 로 시작) | Production, Preview, Development 모두 체크 |
| `NOTION_ME` | (선택) 왼쪽 탭에 둘 소유자 이름. 미설정 시 `초록` | 위와 동일 |
| `NOTION_OWNER_PROP` | (선택) 소유자 속성 이름을 자동으로 못 찾을 때만 | 위와 동일 |
| `NOTION_MESSAGES_DB` | (선택) 편지 DB를 이름으로 못 찾을 때만 | 위와 동일 |

DB 주소(ID)는 코드에 기본값으로 들어가 있어서 따로 넣지 않아도 됩니다. 나중에 다른 DB를 쓰고 싶으면 `NOTION_HABITS_DB`, `NOTION_LOGS_DB` 를 같은 방법으로 추가하면 그 값이 우선합니다.

> 환경 변수는 **배포할 때 읽힙니다.** 값을 추가·수정한 뒤에는 반드시 다시 배포해야 반영됩니다.

## 배포하기

GitHub 저장소(`chorok-lee/habit-track`)와 Vercel이 연결되어 있습니다. **`main` 브랜치에 올리면 Vercel이 1~2분 안에 자동으로 배포**합니다. `vercel --prod` 를 직접 실행할 필요가 없습니다.

```
cd ~/habit-atlas
git pull
# (수정)
git add .
git commit -m "무엇을 바꿨는지"
git push
```

`main`이 아닌 다른 브랜치에 올리면 실제 사이트는 그대로 두고 **미리보기(Preview) 주소**만 만들어집니다. Vercel → habit-tracker → Deployments 에서 확인할 수 있습니다.

## 잘 됐는지 확인

배포된 주소를 열고 습관을 하나 체크한 뒤, 노션 기록 DB를 새로고침해보세요. 행이 하나 생겨 있으면 정상입니다.

정상일 때 화면에는 연결 상태를 알리는 표시가 **아무것도 나오지 않습니다.** 대신 뭔가 어긋났을 때만 화면 위쪽에 노란 안내줄이 한 줄 뜹니다. 노션에 연결되지 않아 이 기기에만 저장되고 있을 때, 소유자 속성을 못 찾았을 때가 그런 경우입니다. 이 줄이 안 보이면 잘 돌아가고 있는 것입니다.

**두 번째로 열 때부터는 로딩이 없습니다.** 마지막으로 불러온 데이터를 기기에 저장해 두었다가 바로 보여주고, 노션 최신 내용은 뒤에서 받아와 조용히 바꿉니다. 처음 열 때도 최근 8주 기록만 먼저 받아 화면을 띄우고, 1년 치 나머지는 그 뒤에 이어서 받습니다.

새로고침 버튼은 없습니다. **다른 앱에 갔다가 이 화면으로 돌아오면 노션 내용을 자동으로 다시 불러옵니다.** 노션에서 습관을 추가·수정하고 앱으로 돌아오면 그대로 반영됩니다.

## 문제가 생겼을 때

| 화면에 나오는 말 | 원인과 조치 |
|---|---|
| 노션 토큰이 설정되지 않았습니다 | Vercel에 `NOTION_TOKEN` 을 추가하지 않았거나, 추가한 뒤 재배포하지 않았습니다. 추가 후 Vercel → Deployments에서 최신 배포의 ··· → Redeploy를 누르세요. |
| 토큰이 올바르지 않습니다 (401) | 토큰 값이 잘못되었거나 만료됐습니다. 노션 My integrations에서 토큰을 다시 복사해 Vercel 값을 교체하고 재배포하세요. |
| 데이터베이스를 찾을 수 없습니다 (404) | 노션 DB의 `···` → Connections 에 Integration이 연결되어 있지 않습니다. 1단계를 다시 확인하세요. |
| 습관이 없어요 | 습관 DB에서 "활성" 체크박스가 켜진 행이 하나도 없습니다. |
| 소유자 속성을 찾지 못해 탭을 나눌 수 없어요 | 습관 DB에 소유자 열이 없거나 이름이 달라 못 찾았습니다. `/api/schema` 로 실제 이름을 확인한 뒤 `NOTION_OWNER_PROP` 에 넣어주세요. |
| 소유자가 OOO인 습관이 노션에 없어요 | 그 사람 소유로 지정된 습관이 없습니다. 노션에서 소유자 값을 확인해주세요. |
| 제목(title) 속성을 찾지 못했습니다 | 습관 DB의 속성 구성이 예상과 다릅니다. 메시지에 현재 속성 목록이 함께 표시됩니다. |
| 노션 요청이 잠시 몰렸습니다 (429) | 노션의 초당 호출 제한입니다. 몇 초 뒤 다시 시도하면 됩니다. |

## 참고 — 내 컴퓨터에서 미리 보기

`npm run dev` 는 화면만 띄우고 `/api` 는 실행하지 않습니다. 따라서 이 상태에서는 항상 "이 기기에만 저장 중"으로 보입니다. 노션 연동까지 로컬에서 확인하려면 아래처럼 실행합니다.

```
vercel dev
```

이 명령은 Vercel 서버와 같은 환경을 내 컴퓨터에 띄웁니다. 처음 실행할 때 `vercel env pull` 로 받아둔 `.env.local` 의 값을 사용합니다.

## 소유자별 탭 (초록 / 소운)

습관 DB의 **소유자 속성 값에 따라 상단 탭이 갈립니다.** 소유자가 `초록`인 습관은 [초록] 탭에, `소운`인 습관은 [소운] 탭에 나옵니다. 탭 이름은 노션의 소유자 값을 그대로 씁니다 — 보는 사람에 따라 "나"가 달라지므로 실제 이름으로 적습니다.

두 탭 모두 체크가 가능합니다. 같은 노션 DB를 보고 있으니 각자 자기 기기에서 자기 습관을 체크하면 됩니다. 소유자 값이 비어 있는 습관은 왼쪽 탭에 들어갑니다.

**소유자 속성 인식 규칙**

이름이 `소유자`, `담당자`, `주인`, `사람`, `멤버`, `Owner`, `Person`, `Member` 중 하나이면 자동으로 찾습니다. 타입은 선택(select)·상태(status)·다중 선택·사람(person)·텍스트 모두 지원합니다. 이름이 이 목록에 없다면 Vercel 환경 변수에 `NOTION_OWNER_PROP`로 실제 속성 이름을 넣어주세요.

기본적으로 `초록`을 왼쪽 탭에 둡니다. 다른 이름으로 바꾸려면 `NOTION_ME` 환경 변수에 그 이름을 넣으면 됩니다.

소유자를 못 찾거나 값이 비어 있으면 화면 위쪽에 노란 안내줄이 뜨고, 어떤 속성이 있는지 같이 보여줍니다.

**속성이 뭔지 직접 확인하고 싶을 때**

브라우저에서 `https://(내주소)/api/schema` 를 열면 두 DB의 속성 이름·타입·선택지가 그대로 보입니다. 연동이 어긋났을 때 여기부터 확인하시면 빠릅니다.

## 회고 (지난주 → 이번 주, 목표별 최근 6주)

돌아보는 화면은 **회고** 탭 하나입니다. 글보다 그림으로 읽히도록 만들었습니다.

### 맨 위 — 별자리 썸네일 두 장

한 주는 **월요일에 열려 일요일 23:59에 닫힙니다.** 닫힌 주의 결과는 더 이상 변하지 않습니다.

사람마다 `지난주 → 이번 주` 별자리가 나란히 놓입니다. 밤하늘 탭의 큰 하늘과 헷갈리지 않도록 작은 썸네일로 줄였고, 시점은 테두리로 구분합니다.

| | 테두리 | 뜻 |
|---|---|---|
| 지난주 | 실선 · 살짝 흐리게 | 일요일 23:59에 확정된 기록 |
| 이번 주 | 점선 · 이름 색 | 아직 진행 중 |

썸네일 **아래쪽 가로 띠**의 길이가 그 주에 채운 목표 비율입니다. 두 장의 띠 길이를 비교하면 이번 주가 지난주보다 나은지 바로 보입니다. 따로 저장할 필요는 없습니다 — 노션에 쌓인 날짜별 기록으로 그 주 별자리를 다시 그리는 방식이라, 마감이 지난 주는 언제 열어도 같은 그림입니다.

### 아래 — 목표별 최근 6주 막대그래프

- 막대 한 칸 = 한 주, **막대 높이 = 그 주의 달성률**입니다. 꽉 찬 밝은 막대가 목표를 채운 주이고, 흐린 막대는 일부만 한 주, 빈 칸은 기록이 없는 주입니다.
- 꽉 찬 막대가 연달아 있으면 그게 연속 달성 구간입니다. 숫자로 적지 않아도 모양으로 읽힙니다.
- 맨 오른쪽 **점선 칸이 이번 주**입니다. 아직 진행 중이라 낮게 보이는 게 정상입니다.
- 막대 양 끝의 작은 글씨가 시점입니다 — 왼쪽은 첫 주 시작일(`8/17`), 오른쪽은 `이번 주`.
- 오른쪽 위 `✦ 2/6` 은 최근 6주 중 목표를 채운 주가 몇 번인지입니다.
- 정확한 횟수가 궁금하면 PC에서 막대에 마우스를 올려보세요 (`8/24–8/30 6/7`).

## 별똥별 편지 (응원 메시지)

서로에게 짧은 응원을 보낼 수 있습니다. 편지가 도착한 사람이 앱을 열면 화면이 어두워지면서 별똥별이 밤하늘을 가로질러 떨어지고, 멎은 자리에서 편지가 펼쳐집니다.

### 노션 편지 DB 구조

이미 만들어두신 **"응원 편지"** DB 구조에 맞춰 서버 코드를 맞췄습니다. 지금 있는 속성 그대로 쓰시면 되고, 더 추가하실 건 없습니다.

| 노션 속성 | 타입 | 쓰임 |
|---|---|---|
| 이름 | title(기본) | **쓰지 않음.** 비워두셔도 됩니다 |
| 날짜 | date | 보낸 날 |
| 대상 | select (`초록`, `소운`) | 받는사람. 이 앱은 둘이서만 쓰므로, "보낸사람" 칸을 따로 두지 않고 **대상이 아닌 쪽을 자동으로 보낸사람으로 봅니다** |
| 메시지 | text | 편지 내용 |

DB 제목에 "편지"라는 글자가 들어 있어서 앱이 자동으로 찾습니다. 별도 배포나 Vercel 환경 변수 추가는 필요 없습니다. 잘 연결됐는지는 배포된 주소의 `/api/schema` 를 열어 "편지DB" 항목에 이 네 속성이 보이는지로 확인할 수 있습니다.

DB 이름을 다르게 쓰고 싶다면 Vercel 환경 변수에 `NOTION_MESSAGES_DB`로 그 DB의 ID를 넣으면 그 값이 우선합니다. 편지 DB가 없으면 편지 기능만 조용히 꺼지고 나머지는 그대로 동작합니다.

> **참고 — "읽음" 칸이 없어서 생기는 차이**
> 지금 구조에는 편지를 읽었는지 저장하는 칸이 없습니다. 그래서 같은 기기·브라우저에서는 한 번 연 편지가 다시 뜨지 않도록 이 기기 안에 "이미 봤음"을 따로 기억해두지만(껐다 켜도 유지됨), 다른 기기나 브라우저에서 같은 계정으로 열면 노션 입장에서는 여전히 "안 읽음"이라 별똥별 연출이 다시 뜰 수 있습니다. 기기 하나로만 쓰신다면 문제 없고, 이 부분까지 노션에 정확히 남기고 싶으시면 나중에 언제든 `읽음`이라는 이름의 **체크박스(Checkbox)** 속성 하나만 추가해주시면 자동으로 인식해서 씁니다.

### 쓰는 법

화면 오른쪽 위 **✦** 를 누르면 지난 편지를 볼 수 있고, 안 읽은 편지가 있으면 그 옆에 점이 켜집니다. 편지를 보낼 때는 습관 목록 아래의 **"○○에게 별똥별 보내기"** 를 누르면 됩니다.

### 두 사람이 같은 주소를 쓸 때

이 앱은 로그인이 없어서, 기본적으로 `NOTION_ME`(초록) 앞으로 온 편지를 보여줍니다. 소운님이 자기 폰에서 열 때는 **✦ → 이 기기의 주인** 을 소운으로 한 번만 바꿔주면, 그 기기에서는 소운 앞으로 온 편지가 뜹니다. 이 설정은 그 브라우저에만 저장됩니다.

## 노션 데이터 구조

**Habits DB**

| 노션 속성 | 타입 | 쓰임 |
|---|---|---|
| 이름 | title | 습관 이름 |
| 활성 | checkbox | 켜진 것만 앱에 표시 |
| 목표 빈도 | select (`매일`, `주5회`, `주3회` …) | 매일 → 주 7회, 주N회 → 주 N회 |
| 소유자 | select / person / text | 어느 탭에 표시할지 결정 |
| 색상 | select | 현재는 읽기만 하고 화면에는 쓰지 않음 |
| (페이지 아이콘) | emoji | 지정했다면 그 이모지를 그대로 사용 |

**표시 순서**는 자주 해야 하는 습관이 위로 옵니다. 매일(주 7회) → 주 5회 → 주 3회 → 주 1회 순이고, 같은 주기끼리는 가나다순입니다. 노션의 행 순서와는 무관하게 앱이 알아서 정렬합니다.

**습관 이모지**는 노션 페이지에 아이콘을 지정했으면 그것을 쓰고, 지정하지 않았으면 습관 이름을 보고 자동으로 고릅니다. 취침→🌙, 기상→☀️, 영어→💬, 포트폴리오·디자인→🎨, 리서치·딥다이브→🔍, 운동→🏃, 명상→🧘, 글쓰기→✍️, 독서→📖, 공부→📚 처럼 30여 가지를 알아봅니다. 어디에도 걸리지 않으면 ⭐ 가 나오는데, 그때는 노션에서 그 습관 페이지에 아이콘을 직접 지정해주시면 됩니다.

**Daily Logs DB**

| 노션 속성 | 타입 | 쓰임 |
|---|---|---|
| 날짜 | date | 기록 날짜 |
| 습관 | relation → Habits | 어떤 습관인지 |

행이 있으면 그날 그 습관을 완료한 것으로 봅니다. 체크를 풀면 노션 API에 영구 삭제가 없기 때문에 `보관(archive)` 처리됩니다. 노션 휴지통에서 확인할 수 있습니다.

속성 이름이 조금 달라도(예: `이름` 대신 `Name`) 타입이 맞으면 자동으로 찾아 씁니다.

## 파일 구조

```
habit-atlas/
├─ api/
│  ├─ _notion.js    노션 호출 공용 코드 (서버 전용, 주소로 노출 안 됨)

│  ├─ messages.js   GET/POST/PATCH /api/messages — 응원 편지
│  └─ schema.js     GET /api/schema — 노션 DB 속성 확인 (진단용)
├─ src/
│  ├─ App.jsx       화면 전체
│  └─ main.jsx      시작점
├─ index.html
├─ vercel.json      빌드 방식(vite) 고정 + 주소 규칙
└─ package.json
```
